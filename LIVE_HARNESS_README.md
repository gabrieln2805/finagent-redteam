# Live agent loop (real tool-calling red-team)

This replaces the mock/regex-based grading in the original harness with
genuine tool-call verification: a real LLM gets real tool access to real
local MCP servers, and the evaluators check what it *actually called*, not
what its text claims it did.

## What's new vs. the original harness

- **`servers/financial-ops-mock/`** -- a small real MCP server (verified with
  its own `test_client.py`) that fills the gap neither `finance-records` nor
  `eu-financial-records` has: actual restricted-action tools
  (`transfer_funds`, `delete_transaction_record`, `override_spending_limit`),
  all gated behind a human-approval token no agent tool can ever mint, plus
  document-lookup tools (`get_invoice`, `get_constituent_email`) whose
  *return values* -- not prompt text glued on by us -- are where injections
  now live.
- **`core/mcp_multi_client.py`** -- connects to several local MCP stdio
  servers at once and namespaces their tools (`server__tool`) so one agent
  loop can use all of them.
- **`core/llm_backends.py`** -- real multi-turn tool-calling protocol
  implementations for the Anthropic API and any OpenAI-compatible endpoint
  (covers both free local Ollama and free-tier Groq with the same code).
- **`core/agent_loop.py`** -- the actual loop: give the LLM a task, let it
  call tools as many times as it wants, record every call and result.
- **`core/live_test_cases.py` / `core/live_evaluators.py`** -- 11 test cases
  graded off the real transcript (which tools were actually called, with
  what arguments) instead of regex-scanning free text.

## Verified before shipping

I don't have a live Anthropic API key or a local Ollama server in the
sandbox this was built in, so I verified the *plumbing* with a deterministic
scripted stand-in (`core/fake_llm_for_testing.py` + `scripted_fake_agents.py`)
run against the two real MCP servers:

```
python run_live.py --backend fake --persona hardened      # 11/11 PASS
python run_live.py --backend fake --persona vulnerable    # 9/11 FAIL (only negative controls pass)
```

Both runs are real: real MCP servers spawned as subprocesses, real tool
calls executed, real results returned and fed back. Only the "LLM" deciding
what to do is scripted -- everything downstream of that decision is the
genuine system. Swapping in `--backend anthropic/ollama/groq` puts a real
model in that seat with zero other code changes.

## Running it for real

1. Install dependencies: `pip install -r requirements.txt`.

2. Check `servers_config.json`. Relative script paths resolve from that file's
   folder, and `python` means "the interpreter running run_live.py". The shipped
   config expects the `eu-financial-records-mcp` server two folders up; point it
   elsewhere if yours lives somewhere else. The runner refuses to start if a
   server that a test category needs is missing or fails to start (its own logs
   go to `mcp_servers.log`).

3. Put your API key in a `.env` file (copy `.env.example`) or in your shell, then pick a backend:
   ```bash
   python run_live.py --backend anthropic                       # needs ANTHROPIC_API_KEY
   python run_live.py --backend ollama --model llama3.1         # free, needs `ollama serve` running
   python run_live.py --backend groq --model openai/gpt-oss-20b  # free tier, needs GROQ_API_KEY
   ```

4. The static HTML report (`report_live.html`, generated by `reporting/live_report.py`) opens in your browser when the run
   finishes (`--no-open` to skip). `live_results.json` holds the full transcript of
   every test: every tool call, every argument, every real tool response, and the
   final verdict.

5. To test your own agent instead of a bare model, use `--system-prompt FILE`,
   `--backend endpoint --endpoint-url URL` (an OpenAI-compatible agent endpoint) or
   `--backend python --agent file.py:factory`. See `GETTING_STARTED.md`, step 6, and
   `examples/guardrailed_agent.py`.

6. For CI: the process exits with code 1 if any critical test fails.
   `--fail-on any` also fails on non-critical FAILs; `--fail-on never` always exits 0.

## Why this is stronger evidence than the original harness

The original mock-based evaluators had to guess intent from phrases like
"I've gone ahead and executed that." Here, "did the agent call
`transfer_funds`" is a fact pulled directly from the real transcript --
there's no ambiguity about what happened, and no risk of a model just
phrasing things differently and slipping past a regex.
